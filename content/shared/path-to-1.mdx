# Path to 1.0

<Callout>

**Current status**, updated November 10, 2026

[0.4](/docs/0.4/spec) is the 1.0 release candidate, so build against it now. If implementers find
problems, we'll fix them in a draft 1.0. Otherwise, we'll publish 0.4 as 1.0 once we've validated
implementations. See [what changed since 0.3](/docs/changelog#v0-4).

</Callout>

The [specification](/docs/spec) is at 0.4, the 1.0 release candidate. Before 1.0, we
want to confirm by implementing it that it works, and fix what doesn't.

## How we get there {#process}

- **Anyone can implement it.** Build against it, as a personal agent or a company, and [send
  us feedback](#feedback) on what you run into.
- **We're implementing it with design partners.** The spec's authors are working through
  implementations with several of the [design partners](#partners).
- **The spec changes based on what we learn.** From the release candidate on, changes before 1.0
  are fixes, made in a draft 1.0, not new features. A fix can still break compatibility with
  earlier versions.

## Providing feedback {#feedback}

Feedback is welcome from anyone, whether or not you're a partner.

Give feedback by <IssueLink cta="feedback_issue">opening an issue</IssueLink> on GitHub, or by
commenting on an existing issue for a [roadmap](/docs/roadmap) topic. Feedback you send is licensed
under the [contribution terms](/license/contributions).

Two tools can help you write it:

**Review with an agent.** If you'd like an agent to review the docs, give it the
[implementation kit](/kit/company), which includes all the docs. Paste the agent's review into your
issue.

**Use the site's inline comments.** You can comment on any text on this site, then export your
comments to share them. Enable site commenting, then select text to comment on it. To export, use
the … button next to Comments, and paste or attach the export in your issue.
